# 海事终端 Android 架构设计与实现计划

## 概述

为 `app/` 模块搭建完整的 Android 应用架构，实现账号管理和账单功能，并预留可扩展框架。同时重构 `cas_lib`，将原型验证代码（main、demo、测试工具）迁移至新模块 `cas_demo`，`cas_lib` 仅保留纯接口实现。`shmtu_ocr/` 不做修改。

## 模块全景

```
shmtu-terminal-android/
├── app/          # 海事终端 Android 应用（Jetpack Compose）
├── cas_lib/      # CAS 认证接口库（纯 JVM，仅接口实现，无 main/demo）
├── cas_demo/     # CAS 接口验证 CLI（纯 JVM 可运行，含 main/demo/测试）★ 新建
├── demo/         # OCR Demo（不可修改）
└── shmtu_ocr/    # OCR 核心实现（不可修改）
```

## 数据库架构：三级独立数据库

核心设计：每个账号一个独立数据库，每个身份一个独立数据库，加上一个主数据库。

```
┌─────────────────────────────────────────────────────┐
│  shmtu_terminal (主数据库)                           │
│  ├── identities 表  (身份元数据)                     │
│  └── accounts 表    (账号元数据)                     │
├─────────────────────────────────────────────────────┤
│  account_{id}_bills (每个账号独立数据库)              │
│  └── bills 表  (该账号的所有账单)                    │
├─────────────────────────────────────────────────────┤
│  identity_{id}_bills (每个身份独立数据库)             │
│  └── bills 表  (该身份下所有账号的合并账单)           │
└─────────────────────────────────────────────────────┘
```

### 为什么独立数据库？

| 优势 | 说明 |
|------|------|
| 隔离性 | 删除账号/身份时直接删库文件，无需逐条删除 |
| 增量查询 | 账号库只含自己的账单，查最新条目极快 |
| 可扩展 | 未来新增账号类型，账单 schema 可独立演化 |
| 并发安全 | 不同账号同步不互相阻塞 |

### 同步流程

```
网络获取账单
    ↓
写入 account_{id}_bills（增量，遇到已有条目停止）
    ↓
新增条目 → 同步写入 identity_{id}_bills
```

### 账单数据库 `account_{id}_bills` / `identity_{id}_bills`

两个数据库共用同一套 Entity + DAO，仅文件名不同。

#### BillEntity (账单条目)
```kotlin
@Entity(
    tableName = "bills",
    indices = [
        Index("accountId"),
        Index("dateTimeStrFormat"),
        Index(value = ["accountId", "transactionNo"], unique = true)
    ]
)
data class BillEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val accountId: Long,            // 来源账号 ID
    val accountLabel: String,       // 来源账号标签（如 "本科"），身份数据库合并查询用
    val dateStr: String,            // 原始日期
    val timeStr: String,            // 原始时间
    val dateTimeStrFormat: String,  // 格式化日期时间（可排序，如 "2024-03-15 14:30:00"）
    val type: String,               // 消费类型
    val transactionNo: String,      // 交易号（增量更新的判断依据）
    val targetUser: String,         // 对方
    val money: String,              // 金额
    val method: String,             // 方式
    val status: String              // 状态
)
```

- **账号数据库**中：`accountId` 始终为该账号自身 ID，`accountLabel` 始终为该账号标签
- **身份数据库**中：`accountId` 标识来源账号，`accountLabel` 标识来源账号标签，用于合并展示时区分来源

#### BillDao (账单数据访问)
```kotlin
@Dao
interface BillDao {
    @Insert(onConflict = OnConflictStrategy.IGNORE)
    suspend fun insertAll(bills: List<BillEntity>): List<Long>

    @Query("SELECT * FROM bills ORDER BY dateTimeStrFormat DESC")
    fun getAllBills(): Flow<List<BillEntity>>

    @Query("SELECT * FROM bills ORDER BY dateTimeStrFormat DESC LIMIT 1")
    suspend fun getLatestBill(): BillEntity?

    @Query("SELECT COUNT(*) > 0 FROM bills WHERE transactionNo = :transactionNo")
    suspend fun existsByTransactionNo(transactionNo: String): Boolean

    @Query("SELECT * FROM bills WHERE accountId = :accountId ORDER BY dateTimeStrFormat DESC")
    fun getBillsByAccount(accountId: Long): Flow<List<BillEntity>>

    @Query("DELETE FROM bills WHERE accountId = :accountId")
    suspend fun deleteByAccountId(accountId: Long)

    @Query("SELECT COUNT(*) FROM bills")
    suspend fun getCount(): Int
}
```

#### BillDatabaseManager (管理多实例)
```kotlin
@Singleton
class BillDatabaseManager @Inject constructor(
    @ApplicationContext private val context: Context
) {
    private val accountDatabases = ConcurrentHashMap<Long, BillDatabase>()
    private val identityDatabases = ConcurrentHashMap<Long, BillDatabase>()

    fun getAccountDatabase(accountId: Long): BillDatabase =
        accountDatabases.getOrPut(accountId) {
            Room.databaseBuilder(
                context, BillDatabase::class.java,
                "account_${accountId}_bills"
            ).build()
        }

    fun getIdentityDatabase(identityId: Long): BillDatabase =
        identityDatabases.getOrPut(identityId) {
            Room.databaseBuilder(
                context, BillDatabase::class.java,
                "identity_${identityId}_bills"
            ).build()
        }

    fun closeAccountDatabase(accountId: Long) {
        accountDatabases.remove(accountId)?.close()
    }

    fun closeIdentityDatabase(identityId: Long) {
        identityDatabases.remove(identityId)?.close()
    }

    suspend fun deleteAccountDatabase(accountId: Long) {
        closeAccountDatabase(accountId)
        context.deleteDatabase("account_${accountId}_bills")
    }

    suspend fun deleteIdentityDatabase(identityId: Long) {
        closeIdentityDatabase(identityId)
        context.deleteDatabase("identity_${identityId}_bills")
    }
}
```

## 核心流程

### 登录流程 (LoginUseCase)
1. 调用 `EpayAuth.testLoginStatus()` 检查会话
2. 如已登录，直接返回成功
3. 如未登录，进入完整 CAS 登录：
   a. `CasAuth.getExecution()` 获取 token
   b. `Captcha.getImageDataFromUrlUsingGet()` 下载验证码
   c. **优先使用本地 OCR** (`shmtu_ocr` 的 `SHMTU_NCNN`)，失败则回退到远端 TCP
   d. `CasAuth.casLogin()` 执行登录
   e. `CasAuth.casRedirect()` 跟随重定向
   f. 验证登录状态

### 账单增量获取流程 (SyncAccountBillsUseCase)

```
┌──────────────────────────────────────────────────────────┐
│ 1. 检查账号登录状态，必要时执行登录                        │
│ 2. 获取第1页 HTML → BillParser 解析                       │
│ 3. 对每条账单：                                           │
│    ├─ transactionNo 已存在？→ 停止获取（已追上最新数据）     │
│    └─ 不存在？→ 加入 newBills 列表                         │
│ 4. 若本页有新条目且有下一页 → 继续获取下一页               │
│ 5. 将 newBills 写入 account_{id}_bills 数据库              │
│ 6. 将 newBills 同步写入 identity_{identityId}_bills 数据库 │
│ 7. 更新 Account.lastSyncTime                              │
└──────────────────────────────────────────────────────────┘
```

**增量判断逻辑**：ePay 账单按时间倒序返回（最新在前）。获取每页后逐条检查 `transactionNo` 是否已存在于账号数据库中，一旦遇到已存在的条目即停止（后续页面均为更旧数据，必然已存在）。

**首同步优化**：如果账号数据库为空（`getCount() == 0`），说明是首次同步，跳过增量检查，获取所有页面。

伪代码：
```kotlin
suspend fun syncAccountBills(account: Account): SyncResult {
    val accountDb = billDbManager.getAccountDatabase(account.id)
    val identityDb = billDbManager.getIdentityDatabase(account.identityId)
    val isFirstSync = accountDb.billDao().getCount() == 0
    
    var pageNo = 1
    var allNewBills = mutableListOf<BillEntity>()
    var shouldContinue = true
    
    while (shouldContinue) {
        val html = epayAdapter.fetchBillPage(account, pageNo)
        val pageCount = billParser.getPageCount(html)
        val pageBills = billParser.getBillTr(html).getBillList()
            .map { mapToBillEntity(it, account.id, account.label) }
        
        if (isFirstSync) {
            allNewBills.addAll(pageBills)
            shouldContinue = pageNo < pageCount
        } else {
            for (bill in pageBills) {
                if (accountDb.billDao().existsByTransactionNo(bill.transactionNo)) {
                    shouldContinue = false
                    break
                }
                allNewBills.add(bill)
            }
            if (shouldContinue) shouldContinue = pageNo < pageCount
        }
        pageNo++
    }
    
    // 写入账号数据库
    accountDb.billDao().insertAll(allNewBills)
    
    // 同步写入身份数据库
    identityDb.billDao().insertAll(allNewBills)
    
    // 更新同步时间
    accountRepository.updateLastSyncTime(account.id)
    
    return SyncResult(newCount = allNewBills.size)
}
```

```
1. 从身份数据库删除该账号的所有账单
   identityDb.billDao().deleteByAccountId(accountId)
2. 关闭并删除账号账单数据库
   billDbManager.deleteAccountDatabase(accountId)
3. 从主数据库删除账号记录
   accountDao.deleteById(accountId)

```
1. 获取该身份下所有账号
2. 对每个账号执行删除账号流程（步骤1-4）
3. 关闭并删除身份数据库

## 注意事项

1. **cas_lib 当前使用阻塞 IO**（OkHttp 同步调用），Adapter 层需要用 `withContext(Dispatchers.IO)` 包装
2. **cas_lib 的 EpayAuth 是有状态的**（持有 cookie），需要为每个 Account 维护独立的 EpayAuth 实例
3. **shmtu_ocr 需要先加载模型**才能使用，需要在 Application 初始化或首次使用时加载
4. **Room 数据库迁移**：后续如修改 schema，需提供 Migration 或使用 fallbackToDestructiveMigration
5. **网络操作需在 IO 线程**，所有 Adapter 方法使用 `withContext(Dispatchers.IO)`
6. **密码存储 key 格式**: `account_password_{accountId}`，在 SecureStorage 中管理
7. **BillDatabaseManager 实例缓存**：使用 ConcurrentHashMap 缓存已打开的数据库实例，避免重复创建；应用退出时统一关闭
8. **删除账号时**必须按顺序：先从身份数据库删条目 → 再删账号数据库文件 → 再删主库记录，否则身份数据库中会残留孤立数据
9. **增量更新依赖 transactionNo 唯一性**：ePay 交易号应全局唯一，`OnConflictStrategy.IGNORE` 配合唯一索引 `(accountId, transactionNo)` 保证幂等
10. **身份数据库是账号数据库的投影**：写入只在同步流程中发生，读取时直接查身份数据库即可，无需运行时合并
