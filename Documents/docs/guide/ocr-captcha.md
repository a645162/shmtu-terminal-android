# OCR 验证码

CAS 登录需要输入验证码。海大终端支持三种验证码处理模式，从手动输入到自动识别，满足不同使用场景。

## CAS 验证码格式

SHMTU CAS 系统使用数学表达式验证码，例如 `3+5=8`。OCR 模型识别出整个表达式后，提取等号后面的答案作为验证码输入。

## 手动输入模式

默认模式，每次 CAS 登录时弹出验证码图片，由用户手动输入。

**优点**：
- 无需额外配置
- 准确率 100%
- 不依赖任何外部服务

**缺点**：
- 每次登录都需要手动操作
- 不适合频繁同步的场景

**适用场景**：首次使用、偶尔手动同步

## 远程 OCR 模式

连接远程 OCR 服务器自动识别验证码。OCR 服务器使用 C++ 实现（Drogon + NCNN），支持 CPU 和 Vulkan GPU 推理。

### 配置步骤

1. 进入 **设置** 页面
2. 将验证码模式切换为 **远程 OCR**
3. 填写 OCR 服务器地址和端口
4. 保存设置

### 服务器部署

OCR 服务器是独立部署的 C++ 服务，位于项目的 `Server/shmtu-cas-ocr-server` 目录。支持 Docker 部署：

```bash
# CPU 版本
docker build -f Dockerfile --target runtime-cpu -t shmtu-ocr-server:cpu .

# Vulkan GPU 版本
docker build -f Dockerfile --target runtime-gpu -t shmtu-ocr-server:vulkan .
```

### 通信协议

客户端通过 TCP Socket 与 OCR 服务器通信：

1. 建立 TCP 连接到服务器地址:端口
2. 发送验证码图片数据（长度 + 图片字节）
3. 接收服务器返回的识别结果字符串
4. 关闭连接

`cas_lib` 中的 `Captcha.kt` 封装了完整的验证码下载和远程 OCR 通信逻辑。

**优点**：
- 全自动识别，无需手动操作
- 服务器端推理，不占用手机资源
- 识别速度快

**缺点**：
- 需要部署和维护 OCR 服务器
- 依赖网络连接
- 服务器不可用时无法登录

## 本地 OCR 模式

使用设备端 NCNN 模型进行推理，无需网络和服务端支持。

### 技术实现

本地 OCR 由 `shmtu_ocr` 模块提供：

- **推理引擎**：NCNN（腾讯开源的高性能神经网络推理框架）
- **图像处理**：OpenCV Mobile
- **接口**：JNI 调用 C++ 推理代码
- **构建**：CMake + Android NDK

调用方式：

```kotlin
val result = predict_validate_code(bitmap)
// result 示例: "3+5=8"
// 提取答案: "8"
```

### 依赖安装

NCNN 和 OpenCV Mobile 的预编译库通过脚本下载：

```bash
python3 scripts/install_lib.py
```

这些库不包含在 Git 仓库中，构建前需要先执行此脚本。

**优点**：
- 离线可用，无需网络
- 无需部署服务器
- 响应速度快（本地推理）

**缺点**：
- 增加 APK 体积（NCNN + OpenCV 库约数 MB）
- 推理速度受设备性能影响
- 模型精度可能略低于服务端

## 模式选择建议

| 使用场景 | 推荐模式 |
|----------|----------|
| 偶尔手动同步 | 手动输入 |
| 每天自动定时同步 | 远程 OCR 或本地 OCR |
| 有 OCR 服务器可用 | 远程 OCR |
| 无服务器、需离线使用 | 本地 OCR |
| 开发调试 | 手动输入 |

## 验证码识别失败的排查

1. **检查验证码图片**：确保网络正常，能正确下载验证码
2. **检查 OCR 服务状态**（远程模式）：确认服务器地址和端口正确，服务正在运行
3. **检查本地模型**（本地模式）：确认 NCNN 和 OpenCV 库已正确安装
4. **切换到手动模式**：如果 OCR 持续失败，临时切换到手动输入避免阻塞
